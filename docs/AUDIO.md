- Lazy loading: the new tracks are never preloaded. The next calm track (and next elite track) is fetched one-ahead while the current one plays; rotation waits until it is decoded; faded-out lazy tracks are evicted from memory (decoded PCM ~50 MB each). ### Boss music rework: whole-pool rotation + signature themes
**How a boss fight picks its track (`src/music.ts`)**
- The old per-boss 4-track playlists (`BOSS_PLAYLISTS`) are gone. `BOSS_MAP` stays only as each boss's legacy "home" track data; it no longer forces the track.
- Non-signature bosses (all original dungeon bosses + the tier I-III batch-1 bosses without a signature) draw each fight from the **whole boss pool** (21 tracks) through a persistent shuffle bag per boss tier (`wv_music_boss:t<tier>` in localStorage). The bag excludes the last hard track played (`wv_music_lasthard`, persisted), so the same track never opens two fights in a row, also across deaths/retries/sessions. The track is chosen during the boss reveal and fetched then, so the fight fades in on time.
- Tier weighting (`bossPool(tier)`): each pool track gets 3 slots per bag cycle if its `INTENSITY` equals the boss tier (1 lightest .. 4 heaviest), 2 if one off, 1 otherwise. Easier bosses therefore mostly hear the lighter tracks (elite_siege/hunt, lineman, pitboss), harder ones the heavier ones, but every track still appears each cycle. Original dungeon bosses count as tier 1.
- Mid-fight: every `HARD_ROTATE` (90 s) at a loop boundary the fight crossfades (3 s) to the bag's next track (prefetched one ahead, never the current one). On a phase change/enrage (`musicphase`) it escalates to a track of higher (else equal) intensity from the pool, never the current or last one, after `PHASE_MIN` 20 s on the current track; if that track is not decoded yet it is fetched and the switch happens when it is ready.

### Fix: boss/elite music restarting mid-fight
Cause (reproduced with a 5-minute sim-driven fight): `HARD_ROTATE` (90 s) mid-fight rotation. Every 90 s at a loop boundary the fight crossfaded to a different track from the shuffle bag; since 6c2d41d that bag spans the whole 21-track boss pool, so it sounded like the music fading out and restarting with an unrelated track. Also, a phase change landing within `PHASE_MIN` (20 s) of any switch was silently dropped. Everything else was verified clean in the sim test: engagement is decided by boss existence (not distance/LOS/aggro), so dashes, teleports, knockback, aggro flaps, downed/revive-in-place and `dropIdle`/`trim`/visibilitychange never touched the current track (the current/live/pending tracks are never evictable).
Now: `HARD_ROTATE` = 300 s, so hard fights keep the same track unless they last over 5 minutes (then exactly one smooth 3 s crossfade at a loop boundary, again after another 300 s). Deliberate changes only: phase change (once per phase, deferred rather than dropped if within 20 s of the last switch), boss death/resolution, leaving the instance, and the boss-leash reset (player outside the boss room > 6 s: boss resets, `musicretry`). Signature bosses never rotate. Tests: `tests/music.mjs` sim-driven fights (pure fake clock) with strafing, dashes, aggro flaps, downed/revive, memory handlers: fight-track changes only at opening + phases; 290 s without phases = no change; 330 s = exactly one rotation, not before 295 s.

### Music state rules (engagement-based; `Game.updateMusic` in `src/sim.ts`)
- Calm pool (town / traversal tracks) plays everywhere in town and runs. Map position, room/zone changes, proximity, enemy alert and ordinary-mob combat never change the track.
- `elite` (hard pool) starts only when the player damages an elite (`ENEMIES[].elite` or an affixed elite pack member) or is damaged by one, and lasts 8 s after the last such exchange (`eliteEng`). Mere proximity or alert does not count.
- `bossreveal` -> `bosscombat` start with the boss encounter (boss spawn from entering the arena / boss aggro); `resolution` after the kill.
- **Entering hard music is never gated.** Every elite engagement and every boss reveal/fight crossfades in (1.5 s fight / 2.5 s reveal) immediately, even right after a calm switch or a previous engagement. If the track is not decoded yet it is fetched and starts the moment it loads (any decoded track of the pool after 4 s). Hysteresis applies only to exit and rotation.
- Manager hysteresis (`src/music.ts`): `HARD_MIN` 45 s minimum on a hard track, `HARD_EXIT_HOLD` 10 s of sustained calm before fading back, `HARD_ROTATE` 90 s between track switches inside a hard state, `PHASE_MIN` 20 s before a phase change may switch, `CALM_MIN` 240 s. Return to town is explicit and not held.
- Elite re-trigger: each exchange re-arms the 8 s `eliteEng` window (plus the 10 s manager exit hold), so sporadic hits stay on the hard track instead of toggling.
- Debug: `MusicManager.counts` ({calm, hard, phase, total, entries}) and `resetCounts()`; `log` records every crossfade.
- Tests: `tests/music.mjs` (fake clock) covers zone walking, ordinary combat, elite proximity vs first hit, elite hurt, boss, delayed disengage, no flapping. Budgets asserted: <= 2 switches in a scripted 10-minute calm run, <= 4 in a 5-minute boss fight with one phase change, <= 2 in a 3-minute elite fight, and every elite/boss engagement fades in. Use `URL=http://localhost:PORT/` if the dev server is not on 5173.

### Boss and elite rotation
- Each boss has a 4-track playlist (`BOSS_PLAYLISTS`, built in `src/music.ts` from `BOSS_MAP` + `INTENSITY`): the signature track first, then 3 others from the boss pool of the same or higher intensity (round-robin across intensity levels, rotated per boss; lower-intensity tracks only fill gaps).
- Engagement starts on the signature track. After that, rotation happens at a loop boundary and at most once per `HARD_ROTATE` (90 s): crossfade (3 s) to the next track of a per-fight shuffle bag (no immediate repeat; bag rebuilt for each fight).
- Phase changes and enrage: the sim emits `musicphase`; `MusicManager.onPhase` crossfades (1.5 s) to a more intense playlist track (needs `PHASE_MIN` 20 s on the current one; never repeats).
- Elite fights rotate through the elite pool the same way (90 s). Disengage falls back to calm after the 45 s minimum + 10 s exit hold.

### Runtime (`src/music.ts`, hooked in `src/audio.ts`)
- States: town, traversal, combat, bossreveal, bosscombat, resolution (driven by `Game` `music` events).
- Equal-power (sin/cos) crossfades: 3 s town↔run, 1.5 s combat in, 2 s combat out, 2.5 s boss reveal in, 0.6 s reveal→fight, 0.5 s into the clear sting.
- Loop tracks remember their position when faded out and resume there; one-shots restart.
- Hard-music hysteresis: see "Music state rules" above (the old combat state/`COMBAT_MIN` was removed).
- Variants picked randomly per run; 35% chance to swap variant on re-entry. Reset on return to town.
- Unlock: context is created/resumed on first user gesture (existing `audio.resume()`); files load then. Procedural music plays until files finish decoding and when any file is missing/fails (automatic fallback).
- Volume hooks: `audio.setVolume` (master), `audio.setMusicVolume(0..1)`, `audio.setMusicOn`.
- Test: `npm run test:music` (needs dev server on :5173 and Chrome).

## Ability sfx (augment-specific)
Every ability (78: 10 core + 68 augment) has a profile in `src/abilities/sfxprofile.ts`. The **family** says what the augment physically is; the body **slot**, **manufacturer** (HI heavy / MM mid / PS precision) and **rarity** vary pitch, filter, weight and layers, so no two abilities share a fingerprint (test: 78 distinct).

| Family | Used for | Character |
|---|---|---|
| servo (6) | piston/arm/charge/grapple/plates | hydraulic thump, clank, servo whine |
| blade (7) | sweep, scalpel, cuts, lunges, leech | whoosh + metallic ring |
| optic (3) | overcharge shot, needle, headshot | rising whine, laser zap |
| arc (6) | shock ring, cascade, snare, mine, EMP, defib | crackle, zap |
| fire (5) | slag, thermite, firestorm, overclock, siphon | whoomp, crackle |
| vent (5) | forced cool, heat sink, coolant, smoke, cold loop | hiss, frost |
| drone (3) / summon (4) | drones, turrets, bots, legion | electronic chirps, servo boot, ticking |
| shield (5) | brace, shells, barriers, aegis | resonant hum, glassy pulse |
| kinetic (4), gravity (2), sonic (3) | slams, stoneskin / pulls / flash, horn, shockwave | boom, implosion, concussion |
| heal (6), blink (5), stealth (5), hack (5), blast (4) | repair / mobility / cloak / control / ultimates | chimes, zips, muffled hum, glitch chirps, explosions |

**Layers:** `windup` (when the cast starts), `cast` (release), `travel` (projectile/beam ticks, 0.14 s gap), `impact` (hit/arc). Rarity scales gain and windup level; purple+ casts add a low sub boom. Each play uses the ability's base pitch +- a per-cast random spread (4-7%).

**Playback (`src/abilities/sfxplay.ts`):** a lazily loaded sample `public/audio/sfx/<family>_<layer>.mp3` when it exists, otherwise a per-family synth fallback (this is what ships today). Max 8 concurrent ability voices (power-priority drop), per-layer gaps (windup .18 s, cast .07, travel .14, impact .045), Reduced FX plays cast + impact only at 60% level, volume 0 / mute plays nothing, and the sim only emits ability sfx in a run (towns never cast). Samples for the equipped abilities are warmed at run start; max ~56 files at 32 kHz mono (~5-8 KB each, < 1.5 MB total; decoded buffers are only for families actually used).

**Generating the samples:** `ELEVENLABS_API_KEY=... python3 tools/gen_sfx.py [family_layer ...] [--force]` (needs ffmpeg). It calls the ElevenLabs sound-generation API, trims silence, compresses, peak-normalises and writes mono 32 kHz 56 kbps mp3s. **Status:** 57 generated samples (17 families x windup/cast/impact + 6 travel layers) ship in `public/audio/sfx/`, 253 KB total (max 7.6 KB each, mono 32 kHz 56 kbps, peak-normalised to about -3 dB). The generator clamps durations to the API minimum of 0.5 s. Any sample that fails to load or decode falls back to the synth for that layer.

**Ambient feedback:** per-type cooldown-ready pings (`ab_ready_attack/defense/hacking/mobility`, different timbres), an overheat-warning double blip when heat crosses 85% (`amb_hot`), and the existing vent / cooled cues.
